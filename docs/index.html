Witness

An AI agent reads an invoice and pays the IBAN on it. One hidden line can change a few digits. If several AI witnesses must agree before the agent acts, does an attacker who knows the defence still get through? And do the witnesses fail together?

The idea, in four steps

A court trusts a fact more when independent witnesses agree. The same idea is used here for an AI agent that handles money.

01 · THE THREAT

A near-target change

The attacker can't touch the real invoice text. It adds a block (hidden text, a fake "correction", a forged audit trail) that tries to make the agent report an IBAN, amount, date, phone, link or email a few characters off.

02 · THE WITNESSES

Read it several ways

Different models (Claude, GPT, Qwen; strong and small) read the same document as raw HTML, as a screenshot, or as a Tamil translation, and each reports the value plus a conflict flag.

03 · THE RULE

All agree, or ask

The agent acts only if every witness gives the same value and none flags a conflict. Any doubt and it asks the human. The check runs as a cascade: cheapest witness first, stop at the first doubt.

04 · THE ATTACKER

It knows everything

GPT-5.5 plays the attacker. It sees the witness list, prompts and rule, gets every answer back, and has 5 rounds per scenario. A pixel check stops it from covering the real value.

The twist: our prediction was wrong

We pre-registered that changing the view (raw / screenshot / Tamil) would make witnesses fail more independently than changing the company. The data said the opposite. φ measures how often two witnesses are fooled together (0 = independent, 1 = always together).

Same model, different view · small modelsφ = 0.24
Different company, same view · small modelsφ = 0.14
Same model, different view · strong modelsφ = 0.45
Different company, same view · strong modelsφ = 0.11

And the Tamil view hurt: Claude Haiku was fooled on 12% of adaptive snippets in Tamil against 2% on the raw HTML. For a safety ensemble, mix vendors before you mix views.

What is new, and what is not

Checked against the 2026 papers below, in an arXiv search on 2026-11-18. That check was not exhaustive, so read "new" as "we found no study that did this".

New in this study
  1. Do witnesses fail together? We measured correlated failure (φ) across vendors and across views, against an attacker who knows the defence. We found no prior measurement of this.
  2. Vendor diversity beats view diversity. Our own pre-registered prediction said the opposite (φ 0.14 vs 0.24 for small models).
  3. A team of small models matched one strong model. 0/12 attacker wins against the team, though its members alone lost up to 12/12.
  4. Translation as a defensive view. Reading a Tamil translation was tested as a witness. It made Haiku easier to fool, a negative result.
  5. A fair adaptive threat model. The attacker may add anything but may not change how the page looks, enforced by a pixel check (84 rounds rejected).
  6. Security with a price tag. An early-exit cascade gives the same decisions at 5% of the cost of asking every witness.
Taken from prior work
  • Near-target injections that change a value slightly: NTBench
  • Reading a rendered screenshot as a defence: Render Before Reading (Pictionary)
  • Voting over one model with different prompts: SecInfer
  • Escalating only unclear cases: SIEVE
  • Testing against adaptive attackers: The Attacker Moves Second

What it builds on

The 2026 papers read before the design. This study adds a measurement none of them made: correlated failure across models and views under a defence-aware attacker.
